# 强化学习挖因子（AlphaGen 范式）

> mentor 方向的终点：把生成器从 GP 换成 RL（PPO/REINFORCE 逐 token 生成表达式），IC 当 reward。
> [因子动物园](./因子动物园.md) 的「生成 ↔ 筛选解耦」架构就是为这一步铺的底座——RL 只换生成器，
> 验证/筛选/deflated 全部复用。

## 核心思想：把「挖因子」变成 MDP

不再进化种群，而是训练一个**策略网络逐 token 生成因子表达式**。

**表达式 = 后缀(RPN) token 序列**：`div(rank(amount), rank(open))` → `amount rank open rank div`。
用栈来建：操作数压栈、算子弹出其元数压回结果——**合法性 = 栈纪律**。

**MDP 四要素**:

| 要素 | 含义                                                               |
| ---- | ------------------------------------------------------------------ |
| 状态 | 已生成 token 序列 + 栈深                                           |
| 动作 | 下一个 token：终端 / 算子 / END                                    |
| 转移 | 追加 token、更新栈深                                               |
| 奖励 | 中间步 0；END 时 = 因子在**同 regime 训练段**上的 \|mean rank IC\| |

**合法性 masking**：每步对词表算 bool mask，非法 token 概率压零（等价于强类型 GP 搬到序列上）。

## 整理成 Token

这里在设计的时候，将表达式进行 token 化了。这么做的原因是，**因子表达式被编码成序列，RL 才能逐步生成**。

我们说表达式本身就是一颗树，但是由于树的动作空间并不固定，结构也较为复杂，所以我们并不会让 RL 模型直接去处理树。而是借用**后缀表达式**的方式，将一个共识展平为一个序列，然后再对这串离散符号进行处理，每个符号就是一个 token。

对这个序列的计算，我们采用**栈**这一数据结构，根据其先进后出的特性，将表达式最外层的算子压到底部，上面逐个压入我们下一步选择的算子，或者弹出算子后的计算结果。

目前对 Token 的分类如下：

| 类型             | 含义                                               |
| ---------------- | -------------------------------------------------- |
| 终端（叶子结点） | 原始数据字段，PRN 栈里压进一个值                   |
| 算子             | 从栈里弹出 n 个操作数，压回计算结果                |
| END              | 告诉 agent 表达式已经生成完毕，继续计算该因子的 IC |

## 四文件架构（src/rl/）

| 文件                                   | 职责                                              | 依赖                                 |
| -------------------------------------- | ------------------------------------------------- | ------------------------------------ |
| [`tokens.py`](../src/rl/tokens.py)     | 词表 + RPN↔Node + 合法性判定（语法层）            | 无（纯 Python）                      |
| [`env.py`](../src/rl/env.py)           | gym 式 MDP：reset/step/legal_mask，END 算 IC 奖励 | pandas，复用 evaluate/calc_ic_series |
| [`policy.py`](../src/rl/policy.py)     | GRU 策略 + rollout 采样 + logprob/熵              | torch                                |
| [`train_rl.py`](../src/rl/train_rl.py) | REINFORCE 训练循环 + 最优因子落盘                 | torch                                |

**关键设计**:

- **窗口烤进 token**：`ts_mean_5/10/20`，每个 token 元数+窗口固定，RPN→Node 一一对应。词表大小 46（6 终端 + 4 二元 + 5 一元 + 9 时序×3 窗口 + 3 ts_corr + END）。
- **预算 mask 的不变式**：除「栈≥arity」外，还要求「放完该 token 后剩余步数 ≥ 新栈深」。这保证 **`remaining ≥ 栈深` 恒成立 → 永远有合法动作能收口**，agent 不会卡死。
- **奖励 = |mean IC|**（不用 ICIR）：复用退化守卫（nunique 中位数 ≥4）挡近常数因子。
- **同 regime 训练**：奖励算在 2021–2022（[regime断点](./regime断点.md) 教训），2023+ 留作 OOS。
- **闭环**：训练完对 top 因子补算 test_ic，存成 `factor_library` 同构 schema → 直接喂 [`screen_factors.py`](../scripts/screen_factors.py) + deflated 盖章，与 GP 因子库走完全同一套尺子。

## 踩的坑（都已修）

1. **`for name in "ts_corr"`**：误把字符串当列表逐字符遍历，造出 21 个垃圾 token。改 `("ts_corr",)`。
2. **`if token.kind == "kind"`**：END 判定字符串写错，END 没被拦截、掉进算子分支，栈深凭空 +1。改 `"end"`。

### 梯度爆炸问题

**`float("-inf")` 做 mask → NaN 梯度**（最隐蔽）：被屏蔽位 `0 * -inf = nan`，`nan_to_num` 只抹前向、**反向梯度仍是 nan** → 污染权重 → 几轮后网络吐全 nan logits 崩。改用大负数 `-1e9`，并加梯度裁剪 `clip_grad_norm_(…, 5.0)` 双保险。

## 强化学习的高方差问题

实际上，reward 是稀疏的，只有在遇到 END 的时候才会给一个数，整条轨迹，大概是十几个 token 的选择，都用同一个标量进行监督。不论标量的好坏都在同一个轨迹里，全都被同一个 IC 值进来衡量，梯度信噪比较低。

## 实测结果（CPU 全量）与收口

### 第一轮：RL 学会了「靠 bloat 过拟合」

全量（iters 300 / batch 64、max_len 20、无 parsimony），探索 **18124** 个因子：

- top 全是 size-19 怪物，train IC 冲到 **0.086**（> GP 的 0.054）——但高出来的全是过拟合：#1 `train +0.086 / test −0.073` **直接翻号**。
- 训练全程**平均奖励几乎不动（~0.01）**：不是在「学信号」，是在「学怎么把 IC 指标玩坏」——树越大越能拟合训练段噪声。和当年 GP bloat / reward hacking 一脉相承。
- deflated（N=18124）✗；那些 sharpe 2+/年化 77% 是 size-19 怪树的截面集中度 artifact（|NW_t| 才 1.14、统计不显著），假的。

### 修法：parsimony + max_len 进 config

`奖励 = |IC| − parsimony·树大小`（parsimony=0.001）+ `max_len=10` 硬卡树大小。两参数进 `configs/*.yaml` 的 `rl:` 段。

### 第二轮：bloat 治住，但撞同一个天花板

- **因子全变 size 7-9，过拟合消失**：rho **+0.856**，top 因子 train/test 同号同量级、不再翻号。
- **但 #1 仍没过 deflated**：N=7262 → E[max t]=3.78 > |NW_t|=2.58。

### 对比随机基线（因子动物园）：RL 没赢

| | 因子动物园（随机生成） | RL |
| --- | --- | --- |
| 探索数 N | 1730 | 7262 |
| deflated 门槛 E[max t] | 3.41 | 3.78 |
| winner \|NW_t\| | **4.22** | 2.58 |
| deflated | ✓ 过 | ✗ 没过 |

RL 搜了 4× 多的因子、撞的还是同一个 amount 天花板（IC ~0.06），winner 反而比**随机生成**的弱。两条硬结论：

1. **生成器不是瓶颈**：GP / 随机 / RL 都撞 amount 天花板，钉死「瓶颈在特征（纯量价），不在搜索机制」——和 STGP 当年一脉相承。
2. **搜索有税**：搜得越多，deflated 门槛越高（选择偏差代价）。RL 探索量大，反而更难过关。

### 收口

RL 工程完整跑通（配置化 / 全存 / N 修正 / joblib 并行落盘 / parsimony 防 bloat），结论诚实：**作为生成器，RL 不优于随机/GP，纯量价天花板照旧**。它的价值是**作为一个可复现的 baseline**——供后续 LLM 辅助生成、PPO、正交数据等方法做 apples-to-apples 对比。

## 状态与诚实限定

- **代码四件套齐全、跑通 CPU 全量、bloat 已修**；REINFORCE 平均奖励训练中**基本不爬**——本宇宙里 RL ≈ 随机搜索（amount 天花板之上没东西可学）。
- **瓶颈在 CPU 不在 GPU**：策略是小 GRU（显存几百 MB），真正耗时是奖励评估（pandas 算 IC，跑 CPU）。「吃满 H100」要等模型做大或把因子求值搬 GPU（cupy/cudf）。
- **这是 REINFORCE v1**：优势归一化 + 熵奖励。PPO（裁剪 + 价值网 + GAE）是后续升级。
- **成败关键仍是 regime 那个 rho**：RL 只换生成器，物理没变——train 2021–22 选、test 2023+ 验，rho 正且 winner 过 deflated 才算真挖到。
